# Shot 1 — Breadth-Complete V1 Alpha

Status: implemented; Shot 2 hardening and release evidence pending.

Shot 1 establishes every major product path behind two public seams:

- `scan(ScanRequest) -> ScanReport` owns one Analysis Scope's source mechanics and rule evaluation.
- `analyze_repository(RepositoryRequest) -> CanonicalReport` owns configuration, independent scopes, policy projection, routes/Page Archetypes, component/repository aggregation, and the canonical envelope.

The CLI is an adapter over the repository interface. JSON, terminal output, Markdown, baselines, feedback bundles, and the GitHub Action do not own separate rule semantics.

## Breadth delivered

- Oxc-based `.jsx`/`.tsx` parsing with per-file failure isolation.
- Nine executable, versioned Slop Pattern paths.
- Fourteen built-in Page Archetypes, safe `unknown`, configured classifications, and declarative custom definitions restricted to built-in structural signals.
- JSONC configuration, monorepository Analysis Scopes, effective-policy fingerprints, House Style primitives/values/signals, narrow Suppressions, and rule dispositions.
- Finding fingerprints and separate evidence digests.
- Finding, Component, and bounded Repository Profiles without cross-scope score blending.
- Four-dimensional coverage envelope with explicit `not_applicable`.
- Canonical JSON schema 1 and a Markdown Refactoring Brief projection with Preservation Obligations.
- Candidate/Reviewed Baseline lifecycle and compatible new/resolved/improved/worsened comparison.
- Advisory and baseline enforcement-shaped exit behavior.
- Complete V1-shaped command catalog.
- Atomic generated artifacts, unrelated-file refusal, symlink/hard-link refusal, and source-non-mutating operation.
- Thin read-only composite GitHub Action and explicit alpha support matrix.

## Deliberately conservative alpha behavior

- Dynamic styling never contributes inferred evidence.
- Design Token Drift is inactive without an explicit approved scale.
- Unknown Page Archetypes remain analyzable and do not count as route failure.
- Custom archetypes cannot define extractors, expressions, score formulas, or code.
- Missing Reviewed Baseline prevents enforcement rather than treating the repository as clean.
- The Action does not download an unverified binary.

## Shot 2 entry conditions

Shot 2 should use failures from real repositories and frozen calibration cases to replace alpha thresholds and incomplete mechanics. Its priority order is:

1. finite class/CVA/wrapper and CSS/Tailwind configuration resolution with reachable-state families;
2. component, import, route, primitive-impact, and Page Archetype graphs;
3. resource budgets, cancellation, safe parallelism, deterministic canonicalization, and hostile-input testing;
4. baseline migration, Trusted Policy, full coverage-floor enforcement, and expiry/unmatched policy diagnostics;
5. measured progress UX, performance, and memory gates;
6. authenticated multi-platform distribution, SBOM/provenance, and immutable Action trust bootstrap; and
7. blind rule/archetype calibration, agent cleanup trials, and customer satisfaction gates.

Passing Shot 1 tests proves breadth and interface coherence. It does not prove V1 precision, recall, usability, platform support, security qualification, or customer value.
