# 0.15 Coverage and Ownership Correction

Status: specialist implementation complete; coordinated SlopSweep corpus qualification pending.

## Problem statement

SlopSweep audited the exact `0.14.0` specialist revision `b70315e` across the real projects directory. Eight repositories were applicable to UI analysis; seven returned incomplete and one completed with Findings. No UI specialist timed out: preserved UI processes completed in 0.009–0.358 seconds. The four recorded specialist timeouts belonged to prose analysis.

The UI completion failures were nevertheless real. Every incomplete scope contained an aggregate style-adapter unresolved entry, and `0.14.0` makes any such entry fatal regardless of its measured coverage. Dynamic style, import, and ownership diagnostics were present, but their numerical coverage remained above the documented blocking floors in the preserved corpus. Additional inspection found irrelevant runtime inline properties counted as missing aesthetic evidence, pathless all-or-nothing CSS diagnostics, semicolon-sensitive external-import parsing, non-application test evidence, and default whole-repository scans when SlopSweep had no reviewed UI configuration.

## Intended outcome

`0.15.0` distinguishes bounded Coverage Limitations from Blocking Coverage Loss. A review may complete with prominent limitations when uncertainty is localized and coverage remains above policy. It remains incomplete when coverage falls below policy, uncertainty has an unbounded blast radius, critical input is missing, or analysis cannot finish reliably.

The correction must improve truthfulness rather than merely reduce exit code `3`. Every coverage unit, warning, blocker, owner, and recovery action must be attributable to canonical evidence.

## Boundaries

Included:

- reachable Style Resolution Units and rule-relevant inline-property accounting;
- path- and use-attributed plain-CSS uncertainty;
- structured Coverage Diagnostics with boundedness and recovery guidance;
- application, test, fixture, and story Source Roles;
- Oxc-derived module, import, export, lazy-loading, and render facts;
- one bounded static-value model for finite class expressions;
- finite Conditioned Ownership Sets;
- unchanged numerical coverage floors followed by corpus recalibration;
- scanner `0.15.0`, report schema `9`, a new beta rule pack, and reviewed baseline migration;
- coordinated SlopSweep Scope Draft and deadline integration.

Excluded:

- arbitrary CSS-in-JS execution;
- complete CSS Modules bundler semantics;
- runtime theme-provider interpretation;
- browser layout or computed-style execution;
- a general CSS cascade engine;
- guessing imports or component owners from names or directory proximity.

## Delivery

### Shot 1: Coverage truth and graph correctness

1. Introduce schema-9 structured Coverage Diagnostics and retain deterministic capped representatives plus total counts.
2. Make the coverage decision use configured dimension floors; remove the unconditional `style_adapter.unresolved.is_empty()` completion gate.
3. Attribute supported plain-CSS uncertainty to affected reachable Style Resolution Units; preserve unbounded/global uncertainty as Blocking Coverage Loss.
4. Ignore runtime-valued inline properties outside the active Rule-Relevant Style Property vocabulary.
5. Classify conventional tests, specifications, mocks, and fixtures as non-application Source Roles; make stories explicitly configurable.
6. Replace text-based module symbol extraction with typed Oxc module facts and eliminate semicolonless external-import false losses.
7. Add public-seam regressions based on ReactPDFRedactor, EventCardSite, WebsiteHelper, and OSM patterns.

### Shot 2: Bounded recall and coordinated qualification

1. Route class composition through one bounded finite-value evaluator supporting literals, concatenation, templates, constant collections, finite branches and switches, side-effect-free local helpers, existing combinators, and CVA.
2. Resolve static component registries and selections into Conditioned Ownership Sets; keep opaque HOCs and unbounded registries localized and unresolved.
3. Implement scanner, schema, rule-pack, migration-preview, and baseline-compatibility version changes.
4. In SlopSweep, initialize a missing UI configuration only inside the disposable snapshot, mark it `generated-unreviewed`, adapt schema 9, and reserve report-writing grace inside the hard process deadline.
5. Pin the corrected specialist revision and repeat the full projects-directory corpus twice.
6. Record semantic result changes, performance, memory, determinism, diagnostic usefulness, and every justified remaining incomplete review.

## Qualification gates

- zero AI UI Slop Bot timeouts;
- no incomplete result caused solely by bounded above-floor limitations;
- concrete affected paths and units for every remaining Blocking Coverage Loss;
- no unresolved local-owner edges for external package components;
- no production Findings or coverage loss from conventional test and fixture modules;
- generated Scope Drafts isolate detected frontend applications;
- irrelevant runtime inline properties do not lower style coverage;
- bounded class maps and component registries resolve deterministically;
- Finding ownership changes are stable or explained by migration output;
- repeated canonical reports are byte-equivalent;
- existing performance and memory gates continue to pass;
- every blocking diagnostic supplies deterministic recovery guidance;
- no requirement that all repositories report complete when genuine blocking uncertainty remains.
