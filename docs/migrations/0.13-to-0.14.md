# Migrating from 0.13 to 0.14

AI UI Slop Bot 0.14 changes report and detector semantics. Treat the upgrade as a reviewed migration rather than silently replacing an enforcement baseline.

## Compatibility changes

| Surface | 0.13 | 0.14 | Required action |
| --- | --- | --- | --- |
| Scanner | `0.13.0` | `0.14.0` | Pin the new exact binary version only after reviewing this migration. |
| Report schema | 7 | 8 | Regenerate reports and update consumers to accept typed scope statuses and `summary.scopeStatuses`. |
| Rule pack | `1.0.0-beta.7` | `1.0.0-beta.8` | Review the semantic report diff; scores and Finding eligibility may change. |
| Cardification contract | `0.1.0-alpha` | `0.2.0-alpha` | Review existing Cardification Findings and baseline matches. |
| Unsupported scopes | Could appear successful with zero Findings | `not_applicable` | Do not interpret unsupported or source-empty scopes as clean UI. |
| Plain CSS | Signal-bearing declarations accumulated conservatively | Later supported declarations in one stylesheet override earlier ones; ambiguous cross-stylesheet classes fail closed | Review removed Findings and new coverage diagnostics instead of assuming either is a clean result. |

Schema 8 also makes `qualified`, `coverage_limited`, and `not_applicable` interpretation states explicit. The Markdown brief includes exact source locations, evidence snippets, and prominent coverage or applicability notices.

## Advisory upgrade

1. Keep the 0.13 report and brief for comparison.
2. Install or build scanner 0.14.0 and confirm `ai-ui-slop version` reports schema 8 and rule pack `1.0.0-beta.8`.
3. Run the same Analysis Scopes and policy in advisory mode.
4. Compare Findings, scope statuses, coverage diagnostics, and evidence. In particular, inspect Cardification changes and plain-CSS override/cross-stylesheet diagnostics.
5. Update report consumers before replacing stored schema-7 artifacts.

## Reviewed Baseline migration

Do not copy a 0.13 Reviewed Baseline forward or accept every changed Finding automatically.

```sh
# Preserve the reviewed 0.13 inputs and generate a 0.14 candidate plus preview.
cp ai-ui-slop.baseline.json ai-ui-slop.baseline.0.13.backup.json
ai-ui-slop baseline create . --force

# Review the semantic migration before approval.
jq . .ai-ui-slop/baseline-preview.json
jq . .ai-ui-slop/baseline-candidate.json

# Only the Design Authority may replace the reviewed baseline.
ai-ui-slop baseline accept . --force \
  --approver "design-authority" \
  --rationale "Reviewed the 0.13 to 0.14 semantic migration"
```

The preview must be fresh and reviewed. Resolve or explain ambiguous, added, removed, changed, worsened, and improved Findings before enabling enforcement. Retain the old baseline until the new enforcement run and repository verification pass.

## CI migration

- Pin `0.14.0` exactly; do not use a floating pre-1.0 version.
- Update schema validation to report schema 8.
- Review any protected Trusted Policy and baseline change together.
- Verify pull-request scans still use policy and baseline inputs from the protected target revision.
- Preserve exit code 3 as insufficient analysis rather than treating it as a clean scan.

The configuration schema remains 1 and the baseline artifact schema remains 2. The semantic compatibility review is still required because the rule pack and Cardification Rule Contract changed.
