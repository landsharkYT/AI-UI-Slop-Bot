# Migrating from 0.14 to 0.15

| Contract | Before | After | Required action |
| --- | --- | --- | --- |
| Scanner | `0.14.0` | `0.15.0` | Pin `0.15.0` exactly after reviewing report changes. |
| Report schema | 8 | 9 | Accept the structured diagnostic fields and the new classification vocabulary. |
| Rule pack | `1.0.0-beta.8` | `1.0.0-beta.9` | Review changed coverage and graph results before accepting a baseline. |

Schema 9 adds `classification`, `bounded`, `affectedUnits`, `relevantSignals`, and
`recovery` to every scope diagnostic. A bounded style-adapter limitation no longer
overrides an otherwise sufficient measured coverage vector. Blocking evidence loss
continues to reduce the relevant coverage dimension and can make a scope incomplete.

Tests, specs, mocks, and fixtures are excluded from the application source role by
default. Story files remain application-visible until an explicit story policy is
configured in a later contract revision.

After upgrading:

1. Run `ai-ui-slop version` and confirm report schema 9 and rule pack `1.0.0-beta.9`.
2. Run an audit and review all `blocking_loss` diagnostics before acting on findings.
3. Compare the result with the prior report; do not treat fewer false unresolved edges
   as a regression.
4. Recreate and explicitly accept the baseline only after that review.
